# Самостійна робота №4: Перевантаження конструкторів

Відповіді на контрольні запитання

1. Навіщо потрібне перевантаження конструкторів у класі Product? 
   Воно дає гнучкість при створенні об'єктів. Товари можна додавати з різним рівнем деталізації: коли відомі всі характеристики, або коли відомі лише базові дані (назва та ціна).

2. Чому конструктор копіювання та скорочений конструктор зручно реалізовувати через `this(...)`?  
   Це дозволяє уникнути дублювання коду ініціалізації полів (принцип DRY — Don't Repeat Yourself). Уся логіка присвоєння значень зосереджена в одному основному конструкторі.

3. Які переваги дає read-only доступ до властивостей після створення об'єкта?  
   Це забезпечує незмінність (immutability) об'єкта. Ключові характеристики товару (наприклад, `Id`) не зможуть бути випадково змінені ззовні після створення, що запобігає помилкам у бізнес-логіці.

4. У яких випадках перевизначення `ToString()` спрощує налагодження та демонстрацію роботи класу?  
   За замовчуванням `ToString()` повертає лише назву типу (`IndependentWork4.Product`). Перевизначений метод дозволяє легко та виразно виводити стан об'єкта в консоль або логи через `Console.WriteLine(product)` без необхідності вручну збирати рядок з багатьох властивостей.
